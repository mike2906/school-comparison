## Outcome

- **P2.14(a) complete locally.** `PipelineRun` now persists a live heartbeat and completed-stage checkpoints. The deterministic stale-run command only selects `RUNNING` rows whose heartbeat predates the supplied cutoff, locks selected rows, marks evidence-bearing runs `PARTIAL`, marks empty runs `FAILED`, and records the counts, last completed stage, completion timestamp, and reason. A terminal rerun is a no-op.
- **P2.14(b) complete locally.** Replacement extraction retains the accepted `data_validation` report, marks the replacement attempt pending, and withholds the replacement payload. Successful deterministic validation atomically promotes the new report and archives the old report. An explicit validation crash persists fail-closed withholding while retaining the old accepted report. Interrupted attempts do not erase accepted evidence or history.
- **P2.14(c) complete locally.** Every tracked billable CLI execution requires a per-run cap. Each dispatch reserves durable ledger capacity before calling the provider, and subsequent dispatch is refused while any attribution is pending/uncertain. Exact provider request ID, run/stage/school identity, model, input/output tokens, provider cost, request/attribution timestamps, and status are persisted. `PipelineRun` final cost prefers exact ledger totals. Reconciliation persists ledger total, provider total, discrepancy, and uncertain count. Missing/delayed attribution fails closed.

Terminal evidence persists URL/page, timeout phase, elapsed time, attempt count, and final reason. The fixed regression cohort is exactly `179, 274, 301, 369, 521, 547, 559, 630, 633`; the fixture proves one terminal timeout does not fail the other eight. No discovery or extraction is invoked by the regression.

Search now evaluates display names through the resolved publication path used by serialization.
